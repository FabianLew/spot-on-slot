# W9: booking screens, plan

Spec: `docs/superpowers/specs/2026-10-06-w9-booking-design.md`.

## Backend (small)
1. `Occurrence.bookingId` -> own calendar (`OccurrenceResponse.bookingId`); public calendar unchanged.
2. `listing.booking_id` (V12), `Listings.markFilled(listingId, bookingId)`, `ListingResponse.bookingId`.
3. `GET /api/v1/bookings?status=` repeatable (any of) for the "Historia" filter.
4. Tests first in `BookingIntegrationTest`; then `pnpm api:generate`.

## Web (`components/bookings`)
1. `queries.ts`: `BOOKINGS`, `useBookings(scope, venueId)` (infinite, 20 per page), `useBooking(id)`, `useAwaitingCount()`.
2. `booking-form-values.ts`: zł <-> grosze, narrowing a picked time (date + hours within the slot), counter values; tests.
3. `booking-cta.tsx`: client button for the public profile, listing page and search cards; role-aware, anonymous -> login.
4. `/bookings/new` (`new-booking-screen.tsx`): venue request (venue switch, free time picker from the public calendar, narrowing, amount, message) or artist application (listing time, amount, message).
5. `/bookings` (`bookings-screen.tsx`, `booking-card.tsx`): filters Czeka na mnie / Oczekujące / Nadchodzące / Historia, venue switch, empty states.
6. `/bookings/[id]` (`booking-detail.tsx`, `counter-dialog.tsx`, `reason-dialog.tsx`): actions by state, stale and calendar-conflict handling, history.
7. Nav badge (`NavItem.badge`), calendar "Zobacz booking", filled listing link.
8. Messages `bookings.*` PL/EN; Vitest per screen; e2e + screenshots `w9-screens/`.
