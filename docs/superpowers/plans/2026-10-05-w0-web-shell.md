# W0 Web Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give `apps/web` a reusable shell (navigation, routes, loading/error states, PL/EN, light/dark theme, base UI components, form pattern, frontend tests in CI) that W1–W15 build on.

**Architecture:** Tokens live in `packages/design-tokens` as CSS variables (`:root` light, `.dark` dark) mapped to Tailwind 4 colors. Base components are shadcn/ui-style in `packages/ui`, free of next-intl (text comes in through props). `apps/web` adds next-intl without locale routing (cookie `NEXT_LOCALE`), next-themes, a route group `(app)` with a shared layout driven by one `navItems` array, and small libs for API errors and forms.

**Tech Stack:** Next.js 16.3.8 (App Router), React 19.2.8, Tailwind 4, next-intl ^4.14, next-themes ^0.4.6, radix-ui ^1.6, class-variance-authority ^0.7, lucide-react ^1.52, sonner ^2, react-hook-form ^7.89, @hookform/resolvers ^5.9, zod ^4, TanStack Query ^5, Vitest ^5 + @testing-library/react ^16 + jsdom.

**Spec:** `docs/superpowers/specs/2026-10-05-w0-web-shell-design.md`

## Global Constraints

- Next.js 16 differs from older versions: read the relevant guide in `apps/web/node_modules/next/dist/docs/` before writing routing, layout, metadata, server action or proxy code. Turborepo: see root `AGENTS.md` before touching `turbo.json`.
- Palette: exact values from spec section 1 table; `index.ts` and `theme.css` must match.
- `packages/ui` never imports `next-intl` or `next/*`; user-visible strings are props.
- All user-visible copy in `apps/web` comes from `messages/pl.json` / `messages/en.json`; Polish default. No invented marketing copy.
- Routes: `/dashboard`, `/calendar`, `/search`, `/messages` (mobile tabs), `/listings`, `/bookings`, `/profile`, `/settings` (mobile "Więcej"); `/` redirects to `/dashboard`.
- Desktop/mobile breakpoint: Tailwind `md` (768 px).
- Locale cookie: name `NEXT_LOCALE`, max-age 1 year, `SameSite=Lax`, path `/`. Supported locales from `SUPPORTED_LOCALES` in `@spot-on-slot/shared`.
- Backend calls only through `@spot-on-slot/api-client`; `ApiProblem` is `components["schemas"]["ProblemDetail"]`.
- Every package with tests has a `test` script (`vitest run`); `pnpm lint && pnpm typecheck && pnpm test && pnpm build` must pass.
- Commits end with the session's attribution trailer lines (given by the controller).

## Review Focus

1. Locale input is junk: cookie `NEXT_LOCALE=de` or `Accept-Language: en-US,en;q=0.9` or `*` — expect fallback to a supported locale (`en-US` → `en`, `de`/`*` → `pl`). Test in Task 5.
2. API returns a non-problem error (HTML 502 from a proxy, empty body, `fetch` rejects offline) — expect `toApiProblem` to produce a usable problem (`INTERNAL_ERROR` / `NETWORK_ERROR`), never throw. Test in Task 8.
3. Validation `errors[]` names a field the form does not have — expect it in the form root error, not silently dropped. Test in Task 9.
4. Nested route (`/settings/notifications` later) — the parent nav item stays active (prefix match, but `/dashboard` must not match `/dashboard-x`). Test in Task 7.
5. Theme loads from storage before hydration — no flash and no hydration warning; `<html>` has `suppressHydrationWarning`. Checked by Task 6 test of the root layout attributes and manual check in final verification.
