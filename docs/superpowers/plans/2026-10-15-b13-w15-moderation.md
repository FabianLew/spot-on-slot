# B13 + W15 moderation and admin panel: implementation plan

Spec: `docs/superpowers/specs/2026-10-15-b13-w15-moderation-design.md`. Fabian chose that blocking cancels upcoming bookings.

## Backend

**Flyway V17 `moderation`:**
- `identity_user` gets `blocked_at` and `block_reason`.
- `artist_profile` and `venue` get `moderation_hidden_at` and `moderation_reason`.
- `listing` gets `moderation_reason`.
- New tables:
  - `moderation_report`: reporter, kind, target id, owner ids, label, reason, description, snapshot jsonb, status, resolution;
  - `moderation_action`: admin, type, kind, target id, subject account, label, reason.

**identity:**
- Events `AccountBlocked(userId, email, locale, reason)` and `AccountUnblocked(userId)`.
- Facade `AccountAdministration`:
  - search with paging;
  - find one account, with its last sign-in from refresh tokens;
  - block and unblock: sessions revoked, the last admin and oneself are refused;
  - admins, and adding an admin through a set-password link that reuses the reset token and an `AdminInvited` e-mail event.
- `AdminBootstrap` (ApplicationRunner) creates `ADMIN_EMAIL`/`ADMIN_PASSWORD` once, verified.
- `Accounts.silenced`, formerly `deletionPending`, also covers blocked accounts, so they get no notifications.

**artist / venue:**
- `hideByModeration(id, reason)` unpublishes and marks the record; `restoreByModeration(id)` clears the mark.
- Publishing a hidden record gives 409 `ARTIST_HIDDEN` / `VENUE_HIDDEN`.
- Responses carry `moderation {reason, hiddenAt}`.
- The facades expose these together with lookups by id or slug (any state) for the admin views.
- A listener on `AccountBlocked` hides, as for deletion.

**listing:**
- `Listings.closeByModeration(id, reason)` closes and stores the reason; the author sees it.
- A listener on `AccountBlocked` closes the person's listings as for deletion.

**booking:** `closeForAccount(userId, venues, reason)` is shared by deletion ("Konto zostało usunięte") and blocking ("Konto zostało zablokowane").

**messaging:** `Conversations.reportSnapshot(conversationId, userId)` returns the other side (owner ids, label) and the last 20 messages; it gives 404 when the caller is not in the conversation.

**notification:** `AccountMailer` sends an e-mail when an account is blocked (with the reason and the contact) and when an admin is invited (with the link).

**moderation (new module):**
- `POST /api/v1/reports` for any signed-in user: target `{kind, slug|id}`, reason, description.
  - Limits: one open report per person and target (409 `MODERATION_ALREADY_REPORTED`) and 10 a Warsaw day (429 `MODERATION_REPORT_LIMIT`).
  - Reporting oneself gives 422 `MODERATION_OWN_TARGET`.
- `/api/v1/admin/**` (`hasRole('ADMIN')`, also in `SecurityConfig`):
  - report targets: grouped list and detail;
  - dismiss;
  - hide and restore artist profiles and venues;
  - close a listing;
  - block and unblock an account;
  - users (search and detail);
  - actions (the log);
  - admins (list and add);
  - the open-report count.

  Every action records a `moderation_action`, and hiding, closing and blocking resolve the matching open reports.
- `PersonalDataSection` "reports" covers the reports the person sent.
- On `AccountDeleted`, the reporter is cleared, the person is removed from owner ids, and actions keep "Usunięte konto".

## Web
- `(admin)` route group at `/admin` with `AdminGate` (ADMIN only).
  - Pages: reports, report target detail, users, user detail, actions, admins.
  - `nav-items` gains admin entries for the ADMIN role, with the open-report badge.
- An ADMIN account on `/dashboard` is redirected to `/admin`.
- `ReportCta` and `ReportDialog` appear on `/a`, `/v` and `/o` and in the chat menu.
- Owners see a "Ukryte przez moderację" notice on their profile or venue status bar, where publishing is disabled; a listing closed by moderation shows its reason.
