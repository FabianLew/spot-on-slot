# W10: message screens, plan

Spec: `docs/superpowers/specs/2026-10-07-w10-messages-design.md`.

## Backend (small)
1. `ConversationResponse.bookingStartsAt` (the booking's current start, via `Bookings.find`) for the "Booking" tag.
2. The messaging unread counter gets its own OpenAPI name (`ConversationUnreadCount`); it clashed with the notification one, so the client saw `{count}`.
3. Assertions in `MessagingIntegrationTest`; then `pnpm api:generate`.

## Web (`components/messages`)
1. `queries.ts`: keys under `["messages"]`, `useConversations(venueId)` (infinite, 20), `useConversation(id)` (null on 404), `useHistory(id)` (newest first, `before` cursor, 50), `useUnreadConversations()`, cache helpers `storeMessage`/`storeOtherRead`.
2. `live-client.ts`: `@stomp/stompjs` client on `liveUrl(API_URL)` (http -> ws + `/ws`), token in CONNECT, refreshed when expiring or after an ERROR frame, auto-reconnect; `live-messages.tsx` mounts it in `(app)/layout.tsx` for ARTIST/VENUE and applies `MESSAGE`/`READ` events to the cache; a reconnect invalidates `["messages"]`.
3. `/messages` and `/messages/[id]` (`messages-screen.tsx`, `chat.tsx`): list beside chat on desktop, one at a time on phones; venue switch; day separators in Warsaw time; "Przeczytane"; older messages on scrolling up; Enter/Shift+Enter, counter from 1800; optimistic send with retry by the same `clientId`; backend errors at the field; block/unblock; marks read while visible.
4. `/messages/new` (`new-message-screen.tsx`) and `MessageCta` ("Napisz") on `/a/[slug]` and `/v/[slug]`; an existing direct conversation opens instead; unpublished sender gets a note.
5. Booking detail "Wiadomości" (`BookingResponse.conversationId`), nav badge `messages`, settings switch `messages.email`.
6. Messages `messages.*` PL/EN; Vitest with the live client mocked; e2e with two browsers + screenshots `w10-screens/`.
